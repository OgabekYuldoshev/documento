# M1: Projects (CRUD + ownership) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any signed-in user can create and manage their own projects; admins/superadmins see and manage all; ownership is enforced by one reusable middleware that later modules (templates, API keys) will reuse.

**Architecture:** New `project` table + `modules/projects` (router -> service -> repository) on the API, `projectProcedure` tRPC middleware that loads the project and checks access from a `projectId` input. Web gets `entities/project`, `features/{create-project,update-project,archive-project}`, `widgets/projects-table`, `pages/{projects,project}`. API logic is covered by Vitest against an in-memory libSQL database.

**Tech Stack:** Hono, tRPC 11, Drizzle + libSQL (SQLite), Zod 4, Vitest (new), React 19, Mantine 9, TanStack Query/Table v9 (`DataTable`).

**Spec:** `docs/superpowers/specs/2026-11-09-projects-templates-generation-design.md` (sections 3, 7, 8, 10 M1). M0 findings: `docs/superpowers/spikes/2026-11-09-typst-m0-results.md`.

## Global Constraints

- SQLite only (libSQL driver); never Postgres. Migrations via `pnpm db:generate`, committed; Better Auth tables untouched.
- API layering: router -> service -> repository; routers never touch the DB; services hold rules; repositories hold queries only.
- Ownership rule (spec 7): a project is accessible iff `project.ownerId === actor.id` **or** actor role is `admin`/`superadmin`. Every project-scoped procedure goes through `projectProcedure`.
- Any signed-in user (including role `user`) may create projects.
- Web follows FSD (`app > pages > widgets > features > entities > shared`, import only downward, slices export via `index.ts`); tables use `DataTable`; forms use `@mantine/form` + `zod4Resolver` with schemas from `@documento/shared`.
- All user-visible text is **Uzbek (Latin)**, straight apostrophe `'`; code, logs, commits English.
- Commits follow Conventional Commits (lefthook commitlint); Biome must pass; `pnpm check-types` must pass.
- `project.retentionDays`: `null` = use global default (`PDF_RETENTION_DAYS`, default 1); when set, integer `1..PDF_RETENTION_MAX_DAYS` (default 30).

## Review Focus

1. **Foreign project id:** a `user` calling get/update/archive with another user's project id gets `NOT_FOUND` (not `FORBIDDEN`: no existence leak); a nonexistent id gets the same error. (Task 4)
2. **Archived projects:** hidden from `list` and unreachable by `get`/`update` for everyone, including admins. (Tasks 3, 4)
3. **Slug generation:** names like `"O‘zbekiston"`, `"Тест лойиҳа"`, `"!!!"`, trailing/leading spaces and two projects with the same name must all yield valid, unique, non-empty slugs (`"project"` fallback, numeric suffix on conflict). (Task 3)
4. **Deleting a user who owns projects:** `users.remove` must fail with a clear Uzbek `CONFLICT` message instead of a raw SQLite foreign-key error or silently deleting projects. (Task 5)
5. **Retention bounds:** `retentionDays` of `0`, `-1`, `1.5` or above the max is rejected with a validation error; `null` clears the override. (Tasks 2, 4)

### Task 3: Projects repository and service (rules)

**Files:**
- Create: `apps/api/src/modules/projects/projects.repository.ts`, `projects.service.ts`, `slug.ts`, `apps/api/test/projects.service.test.ts`, `apps/api/test/slug.test.ts`

**Interfaces:**
- Consumes: `project` table (Task 2), `createUser` (Task 1).
- Produces:
  - `slugify(name: string): string` in `slug.ts`: lowercase, strips Uzbek apostrophe variants (`'`, `‘`, `’`, `ʻ`, `ʼ`) , maps Cyrillic to Latin (basic transliteration incl. `ў->o'->o`, `қ->q`, `ғ->g`, `ҳ->h`, `ш->sh`, `ч->ch`), non-alphanumerics -> `-`, trims/collapses dashes, max 48 chars, `"project"` when empty.
  - `projectsRepository`: `insert(values)`, `findById(id)`, `list({ ownerId?: string })` (excludes archived, newest first), `update(id, patch)`, `archive(id, at: Date)`, `slugExists(slug)`.
  - `projectsService` (all take `actor: { id: string; role: Role }`): `create(actor, input: CreateProjectInput): Promise<Project>`, `list(actor): Promise<Project[]>`, `get(actor, id): Promise<Project>`, `update(actor, input): Promise<Project>`, `archive(actor, id): Promise<void>`.
