# M3: Typst render, preview, publish dry-run (M3a) and assets/queue (M3b)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Templates compile to PDF through a sandboxed Typst child process; the editor shows a live preview; publish is blocked when the template does not compile with its sample data.

**Architecture:** `modules/render/` holds a runner (one Typst process per job, temp dir, resource limits, diagnostics parsing) and a memory-budget scheduler (FIFO, reserves each job's memory limit). `templates.preview` renders unsaved editor state; `publishChecks` reuses the runner. M3b adds `template_asset`, SQLite-backed `generation` queue and restart recovery.

**Tech Stack:** Typst CLI 0.15.1 (child process), Node `child_process`, `prlimit` where available, Vitest, CodeMirror 6.

**Spec:** `docs/superpowers/specs/2026-11-09-projects-templates-generation-design.md` (section 5, 10 M3); measurements in `docs/superpowers/spikes/2026-11-09-typst-m0-results.md`.

## Global Constraints

- Typst is untrusted code: own temp dir per job as `--root`, `--ignore-system-fonts`, `--font-path <FONTS_DIR>`, `--diagnostic-format short`, empty package dirs, `HTTPS_PROXY`/`HTTP_PROXY` pointed at `http://127.0.0.1:1`, no inherited env except `PATH`; `@`-package imports rejected before running (allowlist is empty in M3).
- Limits per job: memory default 1024 MB (`prlimit --as`), CPU = timeout, wall timeout kills the whole process group. Default timeout 60 s, max 300 s. Where `prlimit` is missing (macOS dev) run without the memory limit and log one warning.
- Warnings are errors for publish dry-run (e.g. `unknown font family`).
- Scheduler budget `RENDER_MEMORY_BUDGET_MB` (default 2560); a job larger than the budget is rejected, never queued forever.
- Preview PDF returned inline must be <= 20 MB, otherwise an error says so.
- Env additions go to `config/env.ts` and `.env.example`: `TYPST_BIN` (default `typst`), `FONTS_DIR` (default `./fonts`), `RENDER_MEMORY_BUDGET_MB`.
- UI Uzbek; layering and FSD rules unchanged.

## Review Focus

1. **Escape attempts:** `read("../../etc/hosts")`, absolute paths and `@preview/...` imports fail with a diagnostic, never leak content or touch the network. (Task 1)
2. **Resource bombs:** infinite/huge loops hit the timeout and return `timeout` quickly, leaving no orphan process or temp dir. (Task 1)
3. **Hostile diagnostics:** Typst error text with paths outside the job dir or missing line info still parses to `{message}` without throwing. (Task 1)
4. **Scheduler fairness:** a large job does not starve forever behind small ones; release on failure frees the budget. (Task 2)
5. **Preview with invalid data:** data violating the schema returns validation errors, not a Typst crash. (Task 3)

## M3b plan (assets, storage, persistent queue)

**Global (M3b):** `STORAGE_DIR` (default `./data/storage`) behind a `Storage` interface (local FS now; S3 later); keys are validated (no `..`, no absolute). Assets: png/jpeg/svg images and ttf/otf fonts; name `^[A-Za-z0-9._-]{1,64}$`; extension must match magic bytes; raster <= 40 MP read from the header (decompression-bomb guard); `ASSET_MAX_MB` (default 10) per file, <= 50 files per template. Assets belong to the template (all versions) and appear in Typst as `assets/<name>` (fonts are also added via `--font-path`). webp is deferred (needs a dimension parser).

**Review Focus (M3b):** (1) wrong extension vs. magic bytes, (2) a tiny PNG/JPEG declaring > 40 MP, (3) name traversal `../x`, `a/b`, (4) duplicate name, (5) jobs `processing` at crash time return to `queued` after restart; a worker never runs the same job twice.

- **Task 5 Storage + asset inspection:** `modules/storage/storage.ts` (`put(key, bytes)`, `getPath(key)`, `remove(key)`), `modules/assets/inspect.ts` (`inspectAsset(name, bytes) -> { kind, mime, width?, height? } | throws AssetError`). Tests per Review Focus.
- **Task 6 Asset table, service, upload route, render integration:** `template_asset` table, `assets.service`, Hono `POST /api/templates/:templateId/assets` (multipart, session + ownership), tRPC `templateAssets.{list,delete}`, runner copies assets into the job dir, preview/dry-run use them. Web "Fayllar" tab (upload, list, delete, snippet to copy).
- **Task 7 Generation queue:** `generation` table (status `queued|processing|ok|validation_error|render_error|timeout|expired`), `queue.service` (`enqueue`, worker loop through the scheduler, `recover()` on boot, job data file removed after render, PDF streamed to storage), Hono `GET /api/generations/:id/file`, tRPC `generations.{enqueue (test run from a published version), get, list}`. Tests: enqueue -> ok, crash recovery, validation_error, timeout.
